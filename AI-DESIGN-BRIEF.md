## 7. Known traps — these already broke this site once each

Every one of these was shipped, found by the owner, diagnosed, and fixed. If you reintroduce one you have made the site worse than you found it. Read all ten.

**7a. Tailwind only generates opacity utilities for multiples of five.**
`bg-cream/97`, `bg-cream/92`, `bg-cream/88`, `bg-cream/98` produce **no CSS at all**. The class is silently dropped and the element renders fully transparent. This is why the header and the bottom bar kept "disappearing" over pale sections. The fix is bracket syntax: `bg-cream/[0.97]`. The same trap applies to the duration scale — `duration-400` is not a Tailwind step and emits nothing; use `duration-300` or `duration-[400ms]`.

**7b. Never wrap the route outlet in `AnimatePresence`.**
`<AnimatePresence mode="wait">` around the routes left the incoming route stuck at its `initial` opacity of `0`, producing a completely blank page on every navigation while the fixed header still rendered. Route transitions are now the CSS class `.route-fade` in `index.css`, deliberately **without** `backwards` fill, so that if the animation never runs the content is still visible. An animation that can fail closed is not acceptable on a route transition.

**7c. Native `date`, `time` and `select` inputs have large intrinsic minimum widths, and CSS grid children default to `min-width: auto`.**
That combination made the reservation dialog wider than the phone, and the entire page could be dragged sideways. The fix is `min-w-0` on every grid or flex child that contains one of those controls. Also use `dvh` not `vh` for dialog height — on mobile Safari `90vh` is measured against the largest viewport, so the bottom of the panel is cut off by the browser chrome.

**7d. Raising the drawer above the header hides the close button if the close button lives in the header.**
The drawer went to z-1000 and covered the header that contained its own close control, so the drawer became impossible to close. The drawer must carry **its own header row** with the lockup and a close button, at the same height as the real header, and it must be **fully opaque** (`bg-cream`, no transparency).

**7e. `frontend/public/img/` must stay committed to git.**
Vercel runs only `npm run build`. It never runs `npm run images`. If those generated renditions are gitignored or deleted, every photograph on the production site 404s. When you add a photo, commit the generated files.

**7f. Reference only icon files that exist.**
`public/` was once missing `favicon.ico`, `logo192.png` and `manifest.json` while `index.html` referenced them, which is why the favicon vanished. (The owner suspected the ElevenLabs script; it was not that.) Generate icons with `npm run icons` and make sure every path referenced in `index.html` and `manifest.json` resolves.

**7g. The ElevenLabs widget lives in shadow DOM and cannot be styled from our CSS.**
That is why there is a custom launcher in `ChatAgent.jsx` that calls `startConversation()` on the widget host. Hide the host with `opacity` and `visibility` — **never `display: none`**, because a display-none custom element cannot measure or lay out its own panel, and the chat opens at zero height. The rules are `.tw-agent__host` and `.tw-agent__host--on` in `index.css`.

**7h. `WaveDivider` must render as the first child *inside the lower* of the two sections it separates**, filled with the background colour of the section *above* it, passed as the `from` prop. It cannot be positioned above the boundary because the reviews band and the footer both set `overflow: hidden` and would clip it.

**7i. Bottom-of-page dead space** came from clearance padding sitting on an unstyled wrapper *below* the dark footer, so the page ended in a strip of cream. Any bottom clearance must live *inside* the footer element.

**7j. `REACT_APP_ELEVENLABS_AGENT_ID` is inlined by Create React App at build time.** There is no runtime value. Reading it at runtime yields `undefined`. If the variable is absent at build time, `ChatAgent` must render nothing and must not request the third-party script at all.

### 9.9 Motion

- One easing curve site-wide: `cubic-bezier(0.22, 0.75, 0.18, 1)`, exposed as `ease-brand` in Tailwind and `BRAND_EASE` in `src/lib/motion.js`.
- Durations on Tailwind's scale, or bracket syntax when off-scale (trap 7a).
- Entrances at or below 900ms. Hover and state changes at or below 400ms.
- Reveals fire **once** per page view and translate at most 28px.
- Route changes use the CSS `.route-fade` class with **no `backwards` fill** (trap 7b). No `AnimatePresence` in the file that renders the route outlet.
- At most one decorative loop per viewport, period 3 seconds or longer.
- Animate transforms and opacity only on scroll-linked effects.
- Lenis initialises only at 1024px+, fine pointer, no reduced-motion preference. While it runs, `scroll-behavior: auto` on the document so native and scripted smoothing do not fight.
- Scroll-driven timelines go behind `@supports`; where unsupported the content renders in its final state.
- **Reduced motion**: everything at final position and opacity, durations capped at 0.01ms, parallax off, smooth scroll off. Nothing may be left at zero opacity. Reduced motion means static, not fast.

**The opening sequence** lives as inline CSS and markup in `public/index.html` so it paints before the JS bundle loads, and it uses zero JavaScript. It draws the mark stroke by stroke (rim → bowl → handle → stem → leaf → saucer), fills the leaf sage, raises coffee inside the cup, then the wordmark and subtitle. `pathLength="1"` normalises all six strokes to one dasharray value. Minimum 3300ms so the whole animation is seen, maximum 6500ms, with a 7-second pure-CSS failsafe that dismisses it even if the bundle never loads. `useOpeningSequence.js` coordinates the React side. **It plays on every load — the owner removed the session-skip deliberately.** Do not move this into React and do not add a session check.
